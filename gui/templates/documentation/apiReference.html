About this API0
TestLink 2.0.1 exposes its functionality through a JSON BFF (backend-for-frontend) layer under /api/. Every modern screen talks to these routes; external integrations (CI pipelines, scripts, tools) can call them the same way. All routes return JSON, use the session for authentication and enforce same-origin requests.
Authentication & request contract
Every api route follows the same rules:
  • Session cookie — log in through /login.php (or POST api/auth) and send the session cookie with every request; an anonymous caller receives HTTP 401 with code not_authenticated.
  • Same-origin only — state-changing routes verify Origin/Referer first — a foreign origin is refused with HTTP 403, and only POST is accepted (HTTP 405 otherwise).
  • Session inactivity — a stale session expires server-side and answers HTTP 401 with code session_expired.
  • Error envelope — errors are always JSON: { status: "error", code: "<machine-code>", message: "..." } — branch on HTTP status and code, never on the message text.

Pipeline jobs (GitHub Actions, GitLab CI, Jenkins, Azure DevOps) can publish test results directly — no browser, no XML dialect conversion. POST the CI artifact to the endpoint below with the session cookie of a user holding the test-plan execute right:
/api/cicdpublish/index.php?action=publish format=junit format=json right: testplan_execute
